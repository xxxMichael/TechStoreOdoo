DESCRIPCION DEL MODULO Y DETALLE DE PRUEBAS - TECHSTORE MAINTENANCE
Fecha: 2026-05-29 19:35:00

1. QUE HACE EL MODULO

El modulo TechStore Maintenance para Odoo 16 gestiona el ciclo completo de mantenimiento tecnico de equipos de clientes.

Funciones principales:
- Administracion de clientes vinculados a equipos.
- Registro de tipos de servicio tecnico.
- Registro y administracion de tecnicos con especialidades, estado y disponibilidad.
- Registro de equipos con datos como marca, modelo, numero de serie y cliente propietario.
- Creacion de ordenes de mantenimiento con folio, prioridad, fecha de recepcion, problema reportado y condicion fisica.
- Flujo operativo de ordenes por estados: received, diagnosis, repair, ready, delivered y closed.
- Asignacion de tecnicos a ordenes.
- Registro de diagnostico, trabajos realizados, repuestos usados y resolucion.
- Generacion de auditoria por cambios relevantes en la orden.
- Exposicion de una API HTTP para operaciones CRUD y acciones de negocio.
- Exposicion de un dashboard con metricas operativas y de calidad.

API principal detectada:
- GET/POST `/api/techstore/<resource>`
- GET/PATCH/PUT/DELETE `/api/techstore/<resource>/<id>`
- GET `/api/techstore/dashboard`
- GET `/api/techstore/maintenance-orders/<id>/audit-logs`
- POST `/api/techstore/maintenance-orders/<id>/actions/<action>`
- POST `/api/techstore/technicians/<id>/actions/<action>`

Recursos evaluados:
- clients
- service-types
- technicians
- equipment
- maintenance-orders
- audit-logs

2. DETALLE DE LAS PRUEBAS EJECUTADAS

Las pruebas se ejecutaron directo contra la API autenticada en `http://localhost:8069`, usando sesion de Odoo y validando comportamiento real del modulo cargado en la base `odoo2`.

2.1 Pruebas funcionales

PF-01
- Objetivo: consultar dashboard general.
- Endpoint: GET `/api/techstore/dashboard`.
- Validacion: respuesta HTTP 200 con metricas operativas.

PF-02
- Objetivo: crear una orden de mantenimiento.
- Endpoint: POST `/api/techstore/maintenance-orders`.
- Validacion: respuesta HTTP 201 y estado inicial `received`.

PF-03
- Objetivo: asignar tecnico a la orden.
- Endpoint: POST `/api/techstore/maintenance-orders/{id}/actions/assign-technician`.
- Validacion: respuesta HTTP 200 y tecnico asignado correctamente.

PF-04
- Objetivo: mover la orden a diagnostico.
- Endpoint: POST `/api/techstore/maintenance-orders/{id}/actions/start-diagnosis`.
- Validacion: cambio de estado a `diagnosis`.

PF-05
- Objetivo: comprobar regla de negocio para bloquear reparacion sin diagnostico.
- Endpoint: POST `/api/techstore/maintenance-orders/{id}/actions/start-repair`.
- Validacion: respuesta HTTP 400.

PF-06
- Objetivo: actualizar el diagnostico de la orden.
- Endpoint: PATCH `/api/techstore/maintenance-orders/{id}`.
- Validacion: persistencia del campo `diagnosis`.

PF-07
- Objetivo: pasar la orden a reparacion.
- Endpoint: POST `/api/techstore/maintenance-orders/{id}/actions/start-repair`.
- Validacion: cambio de estado a `repair`.

PF-08

PF-10

- Endpoint: POST `/api/techstore/maintenance-orders/{id}/actions/mark-ready`.

PF-11

- Endpoint: POST `/api/techstore/maintenance-orders/{id}/actions/mark-delivered`.

PF-12
